# 功能限制 {#limitations}

::: warning 使用前请阅读
`pptx-viewer` 覆盖了 OpenXML 规范的较大范围，但部分功能采用近似实现、仅支持读取，或受浏览器平台限制。本页记录已知限制，不代表对所有 Office 功能和第三方扩展的完整兼容性保证。加载演示文稿后请检查 `data.warnings`；正式的覆盖清单见 [OpenXML 支持情况](/zh/architecture/openxml-conformance)。
:::

## 核心引擎（`pptx-viewer-core`） {#core-engine-pptx-viewer-core}

| 功能          | 状态                       | 说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.ppt` 导出   | 部分支持                   | 墨迹、SmartArt、图表和三维模型现在会通过内嵌的 OOXML 往返数据包，在 PowerPoint 中重新打开为可编辑对象（已通过 COM 在 PowerPoint 中重新打开验证）；只有 PowerPoint 97-2003 本身才会看到降级后的回退效果。仍然存在的损失：非 PNG/JPEG 图片会变为占位符，演示文稿自身母版的文本样式覆盖不会写入，视频以及非 WAV 音频会降级为图片，加密 `.ppt` 的导入仅支持 CryptoAPI 的 RC4。详见 [OpenXML 支持情况](/zh/architecture/openxml-conformance#ppt-export-ceiling)。                      |
| SmartArt 布局 | 缺少缓存绘图时采用近似布局 | 未保存缓存 `dsp:drawing` 的演示文稿由逐数据点的 DiagramML 引擎（131 种布局）或较早的按族解释器计算布局。在 229 个通过 COM 创建的图库测试样例中，228 个能生成与 PowerPoint 相同的形状集合，126 个的几何形状误差在 1% 以内（161 个在 5% 以内），114 个的每个字号都一致。框随文本增长的布局（垂直项目符号列表、垂直框列表）、组织结构图中的助理以及 "Meet the Team" 卡片仍不精确。测量依据见 [OpenXML 支持情况](/zh/architecture/openxml-conformance#smartart-layout-ground-truth)。 |

### 动画编辑 {#animation-authoring}

在动画面板中创建的效果会合并到幻灯片已有的 `p:timing` 树中，演示文稿原有的效果保持字节不变。已知的功能缺口：

- **保存的进入/退出效果在 PowerPoint 中会以淡入淡出的方式播放。** 写入器记录了正确的预设，但只写出了淡入淡出行为，因此在此处保存的“飞入”效果，在 PowerPoint 中打开文件时会播放为“淡出”（本查看器则能正确播放）。多个强调效果（脉冲、波浪、跳动、彩色波浪、闪烁、闪光）会被写为空操作。
- **部分滤镜族和预设在播放时采用近似效果：** `strips` 播放为边缘擦除，`wedge` 播放为不断增大的六边形，`slide`/`cover`/`uncover`/`push`/`pull` 共用同一种飞入效果，另有 45 个 PowerPoint 预设 ID 会播放替代效果（例如“基本旋转”和“浮出”都会播放为淡出）。百叶窗、棋盘、轮子和随机线条会忽略其子类型。
- **尚不支持：** 按段落构建时的逐字符波纹效果，以及创建 p15 系列切换效果（文件中已有的会正常播放，但其方向选项会被忽略）；100% 的 `p14:bounceEnd`（已无移动行程，PowerPoint 自身的渲染也不稳定）会被限制为 95%。基于媒体书签的触发器（“书签时”）可在全部五个绑定中创建，“弹跳结束”的回弹曲线已按 PowerPoint 自身的帧拟合。

### 运行时检测兼容性问题 {#detecting-gaps-at-runtime}

无需猜测某个文件是否触及功能限制。加载流程会将许多（但并非全部：例如动画替代效果不会产生任何警告）不支持或近似处理的结构记录在 `data.warnings` 中，其类型为 `PptxCompatibilityWarning`：

```ts
interface PptxCompatibilityWarning {
	code: string; // stable machine-readable code
	message: string;
	severity: 'info' | 'warning';
	scope: 'presentation' | 'slide' | 'element' | 'save';
	slideId?: string; // present for slide/element-scoped warnings
	elementId?: string;
	xmlPath?: string; // where in the package the construct lives
}
```

如果应用需要向用户提示还原度问题，或根据文件情况决定启用哪些功能，请在 `load()` 后检查 `data.warnings`，并在 `save()` 后再次检查。

各部分（浏览器 / Node.js / Web Worker）的运行范围，以及源于浏览器沙箱而非功能缺失的平台相关行为，见[运行环境](/zh/guide/runtime-environments)。

## 各框架组件（React、Vue 3、Angular、Svelte 5、原生 JavaScript） {#framework-viewers-react-vue-3-angular-svelte-5-vanilla-js}

::: warning 基于 CSS 的渲染需要对部分视觉效果作出取舍
幻灯片通过 HTML/CSS 而非 Canvas 显示，可以提供缩放后依然清晰的文本、原生无障碍能力和 DOM 交互。相应的取舍是：少数 PowerPoint 效果没有完全对应的 CSS 表达方式，需要近似处理。
:::

### 近似实现的视觉效果 {#visual-effect-approximations}

| 效果                                                                                 | 状态                                         | 说明                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 三维形状和场景（`a:sp3d` / `a:scene3d`）                                             | 金属材质仍有残留误差                         | 金属材质此前在高仰角光照下会出现过度泛白；现在高光项拥有独立的、有上限的仰角设置，并根据 134 张 PowerPoint 渲染结果重新拟合（在 0-255 的量级上，平均绝对误差从 75.0 降到 36.4），因此仍存在较小的残留误差。2026-09-16 针对 relaxedInset/slope/hardEdge 棱台的修复，尚未针对新的 PowerPoint 渲染结果重新验证。依据见[视觉效果还原](/zh/guide/visual-effects)。 |
| 艺术字包络变形（`inflate` / `deflate` / `can` / `slant` / `fade` / `cascade` / ...） | can 内部轮廓及无法获取字体文件的情况尚未验证 | can 预设现在按照 PowerPoint 实测的线性间距规律放置字形（通过 COM 推导，与曲线调整值无关）。仍待完成：针对 can 预设剩余的内部轮廓误差重新对照 PowerPoint 测量，以及针对无法获取字体文件时使用的描摹轮廓路径对照 PowerPoint 进行验证。依据见[视觉效果还原](/zh/guide/visual-effects)。                                                                          |

倒影、柔化边缘和路径渐变也采用近似实现，但与真实 PowerPoint 的测量结果较为接近。各自的实现方法和 COM 测量依据见[视觉效果还原](/zh/guide/visual-effects)。

### 已知的渲染与编辑缺口（2026-09 审查） {#known-rendering-and-editing-gaps-2026-09-audit}

2026 年 9 月针对真实 PowerPoint 的一次审查发现了以下仍未解决的缺口：

- **保存编辑过的幻灯片仍可能改动少量标记细节。** 公式、换行、继承的格式、母版文本样式、主题背景、批注时间戳、图片填充、媒体单击动作、文本片段的语言和属性、内阴影颜色、渐变内边距以及未改动的图表现在都能正确往返；少量罕见属性（例如部分 `buClr`、`tabLst@algn` 以及动画/音频元数据）在重写的幻灯片上仍可能不同。未被编辑过的幻灯片可以干净地往返转换。
- **文本：** PowerPoint 允许悬挂到右边距之外的中日韩标点（`hangingPunct`）会改为换到下一行，因为只有 Safari 实现了 CSS 悬挂标点；`eaLnBrk="0"` 也不会像 PowerPoint 那样关闭东亚换行（禁则）规则。
- **图表：** 数据标签的标注框和引导线目前只在条形图和柱形图中绘制。
- **动画和切换效果：** 缩放切换效果的方向、在媒体书签上创建触发器，以及 `p14:bounceEnd` 回弹曲线的精确形状尚未与 PowerPoint 一致。
- **三维模型** 会忽略在 PowerPoint 中设置的相机、变换和灯光。
- **编辑器功能覆盖** 仅是 PowerPoint 的一个子集：多个功能区图库尚不可用。编辑顶点（以及任意多边形和曲线绘图工具）、合并形状、画布上的图片裁剪（裁剪手柄、按纵横比裁剪、填充、适应）、选择性粘贴、画布与元素上下文菜单、幻灯片窗格多选、真实的动画预览以及标准编辑快捷键已在全部五个绑定中可用。

## EMF/WMF 图元文件（`emf-converter` 依赖） {#emf-wmf-metafiles-emf-converter-dependency}

::: info 实现位于独立项目
`emf-converter` 是拥有独立仓库的 npm 包，`pptx-viewer-core` 只是使用它。下表记录该包当前的行为；如果与它的版本说明不一致，请以该包自身的版本说明为准。
:::

::: warning 需要 Canvas API
图元文件转换需要 `OffscreenCanvas` 或 `HTMLCanvasElement`。未提供 Canvas polyfill 的纯 Node.js 环境无法处理 EMF/WMF 图像，核心引擎的其他功能仍可正常运行。
:::

| 功能     | 状态               | 说明                                                                                                                                                                                                                                                      |
| -------- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 渐变画刷 | 色标精确且支持平铺 | GDI+ 线性和径向渐变可精确渲染色标、预设、混合系数和变换。自 emf-converter 3.1.0 起，`WrapMode` 平铺在任意角度下均可正常工作，路径渐变也会跟随其边界形状（相对 Windows GDI+ 的偏差在 1-6% 以内，具体取决于平铺模式）。纹理（图片）画刷目前仍渲染为纯黑色。 |
| 光栅操作 | ROP3 精确          | 自 3.1.0 起，`BitBlt`、`StretchBlt` 和 `StretchDIBits` 的全部 256 种 ROP3 代码均可精确求值。按位 ROP2 画笔模式（AND/OR/XOR）为近似实现。                                                                                                                  |
| 文本     | 使用浏览器字体引擎 | 字形度量可能与 Windows GDI 不同。自 3.1.0 起，会遵循 `ExtTextOut` 的 `dx` 数组、`LOGFONT` 高度的正负号以及 escapement 角度；没有 `dx` 数组时，字形间距仍依赖浏览器自身的字体替换。纯 GDI（非 GDI+）图元文件中旋转或倾斜的世界变换不会被应用。             |
