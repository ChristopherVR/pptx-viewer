# Limitations

::: warning Read this before adopting
`pptx-viewer` covers a large surface of the OpenXML specification, but some things are approximated, read-only, or bounded by the browser platform. This page lists only what you **cannot** do, or can only do partially. Anything not listed here loads, edits, renders and saves; see [OpenXML conformance](/architecture/openxml-conformance) for the formal coverage manifest.
:::

### Animation authoring

An effect authored in the animation panel is reconciled into the slide's existing `p:timing` tree; the deck's own effects are left byte-identical. Within that, these are the gaps:

| Area                           | Status                | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------ | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Effect sound (`p:stSnd`)       | Custom file only      | The sound row offers "No Sound" or an audio file chosen from disk. No binding bundles PowerPoint's own stock sounds (Applause, Camera, Chime, and the rest): those assets are Microsoft's and do not exist in this repo, so the picker's second option is "choose a file" rather than a gallery.                                                                                                                                                                                                                                                                 |
| `p:bldP/p:tmplLst`/`p:tmpl`    | Parsed, never played  | A text build's per-level timing templates are typed (`buildTemplates`) and round-trip, but are deliberately not consulted by playback: PowerPoint uses them only to seed timing for an outline level that has no effect yet, and the level on screen already has its own instantiated node under `p:timing/p:tnLst`.                                                                                                                                                                                                                                             |
| `p:animEffect/@filter` `image` | Neutral fade fallback | 26 of the 27 SMIL filter families resolve to a real reveal / conceal effect. `pixelate` is a genuine mosaic built from self-contained SVG `<filter>` data-URIs stepped through discrete keyframes; COM `CreateVideo` frame-diffing shows PowerPoint 2016 itself performs no animation at all for that filter value (it snaps to the end state), so the mosaic is a deliberate substitute with no PowerPoint frame sequence to match. `image` substitutes a second, separately authored image the OOXML payload never carries, so there is nothing to substitute. |

### Tables, geometry, and media editing

| Area                             | Status                   | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `onStopAudio` in headless export | Estimated-duration timer | The `onStopAudio` trigger gates a dependent effect on the real `<audio>` / `<video>` element's `ended` event whether the `p:cond` names its dependency by time node (`@tn`) or by shape (`p:tgtEl/p:spTgt`). With no real media element to listen to (a headless export, or media not mounted on the stage) it falls back to an estimated-duration timer, which is also exactly what PowerPoint itself writes for its own "After Previous" audio chaining (a plain `p:cond/@delay`, COM-verified). |

### Detecting gaps at runtime

You do not have to guess whether a file hit a limitation. The load pipeline reports every unsupported or approximated construct it encounters on `data.warnings`, typed as `PptxCompatibilityWarning`:

```ts
interface PptxCompatibilityWarning {
	code: string; // stable machine-readable code
	message: string;
	severity: 'info' | 'warning';
	scope: 'presentation' | 'slide' | 'element' | 'save';
	slideId?: string; // present for slide/element-scoped warnings
	elementId?: string;
	xmlPath?: string; // where in the package the construct lives
}
```

Check `data.warnings` after `load()` (and after `save()`) if your application needs to surface fidelity notices to users or gate features per file.

## Runtime environments

| Environment              | Works     | Caveats                                                                                                                                                                              |
| ------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Browser                  | Yes       | The full feature set: parsing, rendering, editing, export, collaboration.                                                                                                            |
| Node.js (and serverless) | Core only | `pptx-viewer-core` (load, edit, save, Markdown/SVG conversion, encryption) is DOM-free. The UI bindings, raster export (`html2canvas`), and EMF/WMF conversion are browser features. |
| Web Worker               | Core only | Same scope as Node.js: the engine has no DOM dependency.                                                                                                                             |

## Framework viewers (React, Vue 3, Angular, Svelte 5, Vanilla JS)

::: warning CSS-based rendering trades some visual effects for fidelity elsewhere
Slides render as HTML/CSS rather than Canvas, giving sharp text at any zoom, native accessibility, and DOM interactivity. The tradeoff is that a few PowerPoint effects have no exact CSS equivalent and are approximated.
:::

### Platform-bound behaviour

| Area                 | Limitation                                                                   | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fonts                | Browser font availability                                                    | Text uses fonts available in the browser; missing fonts fall back to system defaults, which can shift text metrics and layout. Fonts embedded in the PPTX are injected when present.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Media codecs         | Browser codec support                                                        | Audio/video playback depends on the browser (WMV and legacy codecs may not play); DRM-protected media will not play.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Morph transitions    | Unmatched elements crossfade                                                 | Elements are matched across the two slides by explicit `!!` naming, `a16:creationId` / native shape-id identity, and same-type proximity. A plain Selection Pane name with no `!!` prefix is not a signal PowerPoint's own Morph honours (confirmed against real PowerPoint), so renaming two shapes to the same name does not make them morph. An element with no counterpart on the next slide crossfades instead of morphing, which mirrors PowerPoint.                                                                                                                                                                                                                                                                                                                                                                                                   |
| Raster export        | `html2canvas` fidelity                                                       | PNG/JPEG/PDF export rasterizes the DOM through `html2canvas`, which cannot reproduce `backdrop-filter`, CSS custom properties, or CSS 3D transforms; approximations are applied and some fidelity is lost. Use the SVG export for a vector alternative.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Export resolution    | Browser canvas cap                                                           | Canvas exports are capped by the browser's maximum canvas size (typically 16,384 or 32,768 pixels per side).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Slide-show shortcuts | `F5` / `Shift+F5` claim the browser's reload key                             | Every binding maps PowerPoint's `F5` (From Beginning) and `Shift+F5` (From Current Slide) whenever the viewer has keyboard focus and no show is running, so a plain `F5` no longer reloads a page the viewer is focused in; `Ctrl+F5` and the browser's reload button are left alone.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Restricted editing   | Salt-less verifiers cannot be checked (not a shape real PowerPoint produces) | A deck saved with a password to modify (`p:modifyVerifier`) opens behind a read-only banner whose "Edit anyway" asks for the password and verifies it against the hash. Every hash algorithm ECMA-376 19.2.1.22 permits is checked: `SHA-1` / `SHA-256` / `SHA-384` / `SHA-512` via Web Crypto, and `MD2`, `MD4`, `MD5`, `RIPEMD-128`, `RIPEMD-160` and `WHIRLPOOL` via pure-TypeScript implementations, including the form real PowerPoint writes (`cryptAlgorithmSid`, no `algorithmName`) and hyphen-less / lower-case `algorithmName` spellings. A verifier with no `saltData` cannot be checked and falls back to an unconditional "Edit anyway"; COM automation (`Presentation.WritePassword` then `SaveAs`) confirmed real PowerPoint always writes a salt, so this is not a shape it produces. The hash is never modified and round-trips untouched. |
| OLE action verbs     | Every verb opens the embedded file                                           | A `ppaction://ole?verb=N` click in a show hands the user the embedding recovered at load time, whatever the verb. PowerPoint dispatches the verb to the application that owns the object (Open, Edit, Play, ...), which no browser can host; an OLE object whose payload could not be recovered consumes the click silently, as PowerPoint does for a broken link.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Run-program actions  | Never executed                                                               | `ppaction://program` ("Run program" action settings) is parsed and round-tripped, but a browser cannot launch a local executable, so the click does nothing in a show.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Small screens        | Dense panels need space                                                      | The UI adapts down to ~360px phones, but the most data-dense panels (for example the full chart editor) are best used on a tablet or larger.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

## EMF/WMF metafiles (`emf-converter` dependency)

::: info Not this repository's code
`emf-converter` is a separate npm package with its own repository; `pptx-viewer-core` only consumes it. The table below records what that package does today, so treat its own release notes as authoritative if the two ever disagree.
:::

::: warning Canvas API required
Metafile conversion needs `OffscreenCanvas` or `HTMLCanvasElement`. Pure Node.js without a canvas polyfill is not supported for EMF/WMF images (the rest of the core engine runs fine in Node).
:::

| Feature           | Status              | Notes                                                                       |
| ----------------- | ------------------- | --------------------------------------------------------------------------- |
| Gradient brushes  | Simplified          | GDI+ linear and path gradients render with their primary colour only.       |
| Raster operations | Not applied         | GDI ROP blending modes (XOR, NOT, AND, ...) are ignored.                    |
| Clipping          | Single path only    | Combined GDI region operations (union/intersect/exclude) are not supported. |
| Output size       | Clamped             | Output is clamped to 4096 x 4096 pixels.                                    |
| Text              | Browser font engine | Glyph metrics can differ from Windows GDI.                                  |
